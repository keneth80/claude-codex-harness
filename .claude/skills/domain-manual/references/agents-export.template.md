## 코딩 규칙 (모든 구현에 적용)
- **단순성**: 문제를 푸는 최소 코드만. 요청 안 한 기능·추상화·예외처리 추가 금지. 과하면 다시 쓰세요.
- **외과적 변경**: 요청과 직접 연결된 라인만. 인접 코드를 임의로 "개선"하지 마세요. 기존 죽은 코드는 두세요.
- **네이밍**: 이름은 의도를 드러냅니다. Boolean은 is/has/can/should, 핸들러는 handle, hook은 use로 시작.
- **주석**: "왜"를 적습니다(무엇이 아니라). 비즈니스 규칙·보안·우회·예외 이유에만. 임시 코드는 TODO/FIXME.
- **보안**: 키·토큰·시크릿을 코드에 직접 쓰지 마세요. 실제 개인정보를 예시로 쓰지 마세요.
- **목표 기반**: 가능하면 테스트로 성공 기준을 만들고 통과시키세요.
- **사전 승인**: 패키지 설치·스키마/인증/배포 변경·대규모 리팩토링은 임의로 하지 말고 먼저 확인하세요.
